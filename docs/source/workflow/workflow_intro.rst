
Task Analysis and Workflow
=====================================

Technical writing focused on technical documentation is creative work. Most creative work can be stated as:

total time = (creative thinking time + productive time) + (overhead time)

where:

- Creative thinking time includes the highest-value work, like analyzing tasks and finding gaps, researching, interviewing, structuring content, solving problems, creating graphics, etc. 
- Productive time includes high-value work, like writing initial content, testing content, updating content based on reviews, checking requirements and features, etc.
- Overhead time includes low-value but necessary tasks or work like, attending non-critical meetings, reminding reviewers about feedback, consolidating feedback, completing release checklist, publishing content to expected channels, etc.

The total quantity of creative thinking time + productive time is where the value of technical writing really happens. This is the amount of time that should be prioritized, protected, and expanded. Unfortunately, most of the time spent in technical writing is actually spent in the overhead time category. Overhead time is where writers typically have to find hacks or work around solutions to work efficiently. This is the area where automation can be most helpful.
